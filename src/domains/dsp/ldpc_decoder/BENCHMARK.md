# CPU LDPC baseline

Build only the module test target, then run the Python wrapper:

```
meson compile -C build -j 5 jetstream-modules-dsp-ldpc_decoder-module-tests
python src/domains/dsp/ldpc_decoder/benchmark.py --build build --output report.json
```

The runner never builds. The benchmark is an opt-in Catch2 test, excluded
from normal test runs. A report is written only after all correctness
checks pass. Keep reports outside the source tree.

## Workload and correctness

The separate 64-frame corpus has eight frames per condition: -1, 1, 2,
2.5, 3, 4, 6 dB and a noise-free channel (100 dB is a sentinel for sigma=0).
No frames are discarded. Transmitted codewords and reference-decoder output
are separate: failing to recover a low-SNR codeword is expected; disagreeing
with the reference decoder fails the benchmark.

The corpus is generated by LDPC-Project's `golden_export output.hh --benchmark`,
using its encoder, rate-aware AWGN and CSR decoder, seed 42. Regeneration
may differ across standard libraries; committed fixtures and their report
hashes identify the exact workload. The original twelve golden frames remain
the fast regression set.

Batch sizes are 1 and 64, with sequential CPU lanes, not CPU multithreading.
Each condition and an all-condition mixed workload rotates frames between
trials. Five warm-ups precede 51 measurements. Every output is checked
outside the timed interval. Setup is excluded; runtime dispatch and the
TestContext output snapshot are included. Raw batch times, medians,
amortized per-frame time, median-derived throughput and aggregate throughput
are saved. Information throughput counts 1024 bits per attempted frame;
it is not successfully delivered goodput. Reference convergence and truth
bit-error totals describe the measured frames, not the warm-ups.

## Interpretation

This is a finite, warm-cache baseline, not a statistical BER study or a
fixed-work CPU/GPU comparison. Iteration totals are reference expectations,
not module telemetry. Early termination is enabled with a 50-iteration cap.
The implementation is labelled `cpu-generic`: compiler auto-vectorization
may be present, so it must not be described as a guaranteed scalar baseline.

Reports record hostname, hardware, OS, Meson compiler/options/target settings,
revision, working-tree status, executable hash and corpus hash. Compare
implementations on the same machine with matched workloads/settings.
GPU and explicit SIMD variants are not implemented by this harness yet.
